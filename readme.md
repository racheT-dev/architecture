# Лабораторная работа №1: Реализация готовой продукции

## Тема предметной области
Оптово-розничная торговля товарами. Отслеживание финансовой стороны работы компании, учет товаров, покупателей и документов по сделкам.

---

## 1. ER-модель предметной области (3НФ)

Модель состоит из 3-х независимых и зависимых сущностей, приведенных к Третьей нормальной форме (3НФ): все неключевые атрибуты зависят от первичного ключа, нет транзитивных зависимостей и повторяющихся групп.

### Таблица 1: Products (Товары)
| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INT (PK) | Уникальный идентификатор товара |
| `name` | VARCHAR | Наименование товара |
| `wholesale_price` | DECIMAL | Оптовая цена |
| `retail_price` | DECIMAL | Розничная цена |
| `reference_info` | TEXT | Справочная информация о товаре |

### Таблица 2: Customers (Покупатели) ⭐ *Выбрана для ЛР1-ЛР4*
| Поле | Тип | Описание |
|------|-----|----------|
| `inn` | VARCHAR (PK) | **ИНН организации** (уникальный бизнес-ключ, заменяет технический ID) |
| `name` | VARCHAR | Наименование покупателя (организации/ИП) |
| `address` | VARCHAR | Юридический/фактический адрес |
| `phone` | VARCHAR | Контактный телефон |
| `contact_person` | VARCHAR | ФИО контактного лица |

> **Примечание:** В качестве первичного ключа используется `inn` (бизнес-ключ), а не абстрактный `id`, так как это реальный уникальный идентификатор юридического лица в РФ, что соответствует лучшим практикам проектирования БД.

### Таблица 3: Transactions (Документы/Сделки)
| Поле | Тип | Описание |
|------|-----|----------|
| `id` | INT (PK) | Уникальный идентификатор документа |
| `customer_inn` | VARCHAR (FK) | Внешний ключ → `Customers.inn` |
| `product_id` | INT (FK) | Внешний ключ → `Products.id` |
| `quantity` | INT | Количество купленного товара |
| `purchase_date` | DATE | Дата совершения покупки |

### Связи между сущностями:
- **Customers ↔ Transactions**: `1:N` (Один покупатель может совершать множество сделок).
- **Products ↔ Transactions**: `1:N` (Один товар может фигурировать в множестве сделок).

### Обоснование выбора сущности для реализации:
Выбрана сущность **Customers**, так как она является независимой и имеет наибольшее количество полей (5 полей), что позволяет полноценно продемонстрировать инкапсуляцию, валидацию и перегрузку конструкторов в последующих пунктах лабораторной работы.
